Demo Editor

A live production workspace for building a show without leaving the engine. Edit the .nsd document, preview the real runtime, tune the timeline and camera, and save or export the result from one dockable interface.

Read the NSD scripting reference →

Start the editor

Build the application, then launch the editor against the production you want to author. The editor uses the same renderer and director as standalone playback.

terminalbash
# open the default production
./build/Release/ns_demo.exe --editor --demo=data/demo.nsd

# open a different project
./build/Release/ns_demo.exe --editor --demo=data/my_show.nsd

# optional: start without restoring an audio track
./build/Release/ns_demo.exe --editor --demo=data/my_show.nsd --no-track
Paused by default

The editor opens at 0:00 with the first scene rendered but the show stopped. Press Space or click Play when you are ready to run the transport. Standalone playback still starts automatically.

Workspace

Panels are dockable and their layout is saved in imgui.ini. Toggle them from View; use View → Reset Layout if a panel is lost or docked somewhere unexpected.

▣

Viewport

The actual runtime frame. Select nodes, drag assets onto it, use right-drag for fly camera, and inspect the result at the current playhead.

☷

Hierarchy

Scene list and scene-graph nodes. Select a scene to edit its setup, then select a node to edit its transform and payload.

◈

Inspector

Transforms, text, models, sprites, lights, particles, camera rigs, visibility, and scene transition controls.

▤

Timeline

Full-show lanes, scene sections, markers, waveform, FFT strip, beat grid, scrollbar, and Fit-to-show navigation.

⌘

NSD Commands

Templates and an editable source field for commands that are not represented by a specialized inspector.

ƒ

Shader Lab

Typography-focused live fragment-shader workspace with presets, parameters, text, compilation diagnostics, and export into the show.

Projects and documents

The editor treats the parsed production as a document, then serializes edits back to NSD. The runtime parser remains the source of truth for playback.

CommandAction
File → Load Project (.nsd)…Open another .nsd project through the file dialog and switch the live preview to it.
File → Save Project (.nsd)Serialize the current document to its existing project file. An asterisk in the title marks unsaved changes.
File → Save Project As…Write the current production to a new .nsd path and make that document the active project.
File → New Project (.nsd)…Create a minimal production from scratch, ready for scenes and timeline events.
File → Open AssetBrowse Audio, Texture, Shader, Model, or Script files and apply the selected asset to the relevant editor or preview action.
Save often

Authoring changes are live in the preview, but they are not a replacement for saving the document. Use Ctrl+S where available, or File → Save Project (.nsd) before switching projects.

Transport and long shows

The timeline is designed like a video editor: the visible window can be zoomed and panned independently of the show duration.

ControlBehavior
Space / PlayStart or pause playback. Editor startup is stopped.
R / RestartReturn to 0:00 and rebuild the active scene.
.Advance one frame while stopped.
Timeline scrubSeek the show and re-establish the scene at the target time; audio follows the playhead.
Fit / FFit the entire project duration in the timeline. Press again to restore the previous zoom and scroll position.
ScrollbarPan through a long production without changing zoom. The handle shows how much of the show is visible.
Q / Shift+QToggle beat snapping and cycle beat/bar quantization.
F2Reload the NSD script from disk.

The view window is remembered per project in data/editor_state.json, so loading a project restores the last zoom and scroll position instead of hiding the later sections of a long show.

Audio and BPM

Load a track from File → Open Asset → Load Track…, the TRK button, Ctrl+T, the asset browser, or an OS-level drop onto the waveform strip.

  • WAV/MP3/OGG/FLAC files are decoded asynchronously so the editor remains responsive.
  • The audio analysis detects kicks and estimates BPM automatically when a track is loaded.
  • The detected BPM is applied to the project, serialized into the active .nsd, and used immediately for bars, beat grid, timeline snapping, and audio-reactive playback.
  • The waveform, FFT spectrogram, kick markers, beat grid, and phase alignment tools live in the Timeline panel.
  • Use Align beats to kicks when the BPM is correct but the track phase needs nudging. The alignment is stored per track.
project headernsd
demo "MY SHOW" {
    bpm 128
    duration 346
}

Scenes and NSD commands

Use the scene list to jump directly to a scene declaration. Specialized inspector controls cover common edits; View → NSD Commands exposes the complete command vocabulary when a production needs something more specific.

data/my_show.nsdnsd
scene Core {
    camera CoreCam { rig orbit; target (0,0,0); radius 5; omega 0.4 }
    shader neural_core.frag
    text caption { text "MEMORY RECOVERY"; size 32; pos (0,1,0) }
}

at 32 {
    show Core
    camera CoreCam
    marker CORE
}

In the NSD Commands panel, choose a command template, edit its generated source, then insert it into the selected scene setup or at the current playhead. The editor parses and validates the command before saving and rebuilding the preview. This is the escape hatch for show, hide, load, shader, post, anim, marker, mesh, sprite, image, text, light, particles, and other runtime commands.

Camera rig authoring

Select a scene, open its Camera Rig section, and edit the rig without hand-writing every camera option. Changes are written back to the scene camera command and reloaded into the preview.

PropertyPurpose
Camera typeStatic, Drift, Fly, Nave, Orbit, Spiral, Hover, City, Descend, or Path.
Position / TargetCamera pose and look-at point.
Sway / Amplitude / FrequencyProcedural movement and per-axis motion.
Speed / Orbit radius / Orbit omegaMotion parameters for traveling and orbiting rigs.
FOV / DOF focus / DOF apertureLens and depth-of-field controls.
Handheld / Descend rate / Descend capShake and specialized rig behavior.

If a scene has no camera command, use Add camera rig in the inspector to create one, then select the rig type from the combo box.

Scene transitions

Scene-level transitions are edited in the Inspector rather than hidden in timeline source.

ControlSerialized form
Transition In → Fade + durationfade in 1 in the scene setup.
Transition Out → Fade + durationA scene-relative cue such as at 11 { fade out 1 }, placed at the scene end.
NoneRemoves the corresponding transition behavior.

Existing transition fade 1 cues are recognized as transition-out settings. Use the editor controls for consistent timing, then preview the boundary by scrubbing across the scene edge.

Assets, shaders, and Shader Lab

The editor uses one asset workflow for disk files, browser rows, OS drops, and live previews.

  • Shader: choose a .frag in File → Open Asset to display it live in the viewport. A shader can also be dragged onto the viewport. Add to Scene copies it into shaders/, inserts a shader command, and saves the project.
  • Model: browse or drop .obj and .glb assets to warm the model path or assign them through a scene command.
  • Image: use an image node and its transition options for textured entrance animations.
  • Fonts: text nodes and Shader Lab can use multiple TrueType/OpenType files from assets/fonts/; leave the text-node font field blank for the project default or enter a path such as assets/fonts/intro.ttf.
  • Texture: drop a texture onto a selected Sprite node to assign it immediately, or use a Shader Lab fill texture for image-driven glyph colour.
  • Script: open another .nsd from the browser to switch projects.

Shader Lab

Open View → Shader Lab to show the typography-oriented shader workspace. Enter text, choose any discovered font, select a preset, tune parameters, map controls to audio-reactive values, and choose a fill texture from assets/textures/ or data/textures/. Texture mix, scale, and motion controls create colourful image-driven fills instead of a flat colour. Edit the generated GLSL and compile it live. Use Export / Add to Scene to place the result into the production; the selected font and texture are serialized with the shader command so playback matches the preview. The underlying shader source remains available for advanced edits.

Preview isolation

Changing scenes or selecting another shader clears the previous editor-only preview. If a shader compiles incorrectly, the diagnostics appear in the Console and the previous valid program is retained by the live-reload path.

Export and distribution

The editor can hand the project to the same capture and packaging systems used by the command line.

Menu actionResult
File → Export MP4…Choose an output path and render the show through the capture pipeline. Set the resolution, FPS, and optional audio source in the export dialog.
File → Package Project…Create an .nsp asset package from the project and its dependencies.
File → Export Distribution…Assemble the package, engine executable, and a launch.bat with the correct command-line switches, then create a ZIP for sharing.
equivalent command-line playbackbash
./build/Release/ns_demo.exe --pack data/my_show.nsd --output MyShow.nsp
./build/Release/ns_demo.exe --play MyShow.nsp

Recommended authoring loop

  1. Open the project and load its track. Let automatic BPM detection establish the beat grid.
  2. Press F in Timeline to fit the whole show, then zoom into the section you are editing.
  3. Select a scene from the scene list and tune its Camera Rig, transitions, nodes, and text in the Inspector.
  4. Use NSD Commands for anything not covered by a specialized control; keep the generated source small and validate before inserting.
  5. Drop shaders, models, images, or textures onto the appropriate panel and inspect compile/load messages in Console.
  6. Save the .nsd, run a short MP4 preview, then package the final project for distribution.
