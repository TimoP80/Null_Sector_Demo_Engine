NULL SECTOR AI SHADER GENERATOR

Describe a demoscene effect, generate ordinary editable GLSL, compile it through the real Null Sector shader path, iterate with AI or by hand, and export portable shader assets.

Launch

The generator is a separate application; it does not add AI code or editor dependencies to the runtime player.

terminalbash
# build the workstation
cmake -S . -B build -DNS_BUILD_APP=ON
cmake --build build --config Release --target ns_shader_ai

# open the interactive workstation
./build/Release/ns_shader_ai.exe

# verify generation, pair compilation, failure recovery, metadata and project IO
./build/Release/ns_shader_ai.exe --smoke
Separate target

ns_demo.exe remains runtime-only. ns_editor.exe remains the production editor. The shader workstation reuses the engine's GLSL loader, OpenGL context, fullscreen geometry, VFS mounts and Dear ImGui without becoming part of playback.

Shadertoy import / converter

The tool converts Shadertoy GLSL — or a Shadertoy JSON API export — into a single Null Sector fragment shader with every channel folded into one file. Buffer passes become callable vec4 functions; texture channels stay sampler2D uniforms (bind at runtime); audio/keyboard channels are stubbed. Uniforms are remapped to the Null Sector set (uResolution, uTime, uBass, …).

Interactive import

File → Import Shadertoy…  (or Ctrl+I)

# paste single-pass code, the engine's `// pass:` marker format, or a JSON export
# click Convert → the result loads into the editor and previews immediately

Headless conversion (--convert-shadertoy)

The same conversion runs without a window or GL context, so it slots into build scripts and CI. The --smoke self-test covers it headlessly: generation, pair compile, failure recovery, multi-pass folding, JSON export parsing and a compile of the converted output.

terminalbash
# single-pass: data/shadertoy/plasma.glsl
./build/Release/ns_shader_ai.exe --convert-shadertoy=data/shadertoy/plasma.glsl --out=plasma.frag

# multi-pass (shipped example: common + buffer_a + buffer_b + image)
./build/Release/ns_shader_ai.exe --convert-shadertoy=data/shadertoy/multipass_example.glsl --out=multipass_example.frag

# Shadertoy JSON API export (renderpass[] code + names)
./build/Release/ns_shader_ai.exe --convert-shadertoy=shadertoy_export.json --out=shadertoy_export.frag
  • --out=FILE is optional — it defaults to the input path plus .frag.
  • Exit code 0 on success; 1 on failure (unreadable input, or JSON that is not a Shadertoy export).
  • The emitted file starts with #version 300 es; the engine's loader rewrites it to desktop 330 core, so the result compiles and renders through the normal shader scene path or Shader Lab without further work.

Input formats

  • Single-pass GLSL — the whole file is the image pass.
  • Multi-pass with // pass: markers — common (header helpers), buffer_a…buffer_d, image; channel defaults and overrides are described under Channel wiring below. See Shadertoy Import for the full marker rules.
  • Shadertoy JSON API export — {"Shader": {"renderpass": [...]}} (the array-wrapped bulk form and a top-level renderpass are accepted too). Each pass's code is extracted and its name is mapped onto a pass marker, case-insensitively so localized names degrade gracefully:
renderpass namebecomes
Common// pass: common
Buffer A … Buffer D// pass: buffer_a … buffer_d
Image// pass: image
Sound / Cube A…D / unknownskipped, with a note

JSON that parses but has no renderpass array fails with JSON input is not a Shadertoy export (no renderpass array) instead of emitting broken GLSL. Each renderpass’s inputs array is mapped to channel wiring (texture/cube/video inputs become bindable samplers, buffer inputs fold to the matching buffer pass, audio/keyboard are stubbed); unwired channels follow the engine convention below.

Inside the file: a header comment lists the folded buffers and any sampler channels to bind at runtime; the standard uniform shim (uResolution, uTime, uBass, …) plus the i* compatibility defines is emitted; each buffer pass becomes a st_<name> vec4 function with its helper functions name-prefixed so passes cannot collide; and a main() wrapper calls the image pass. The emitted .frag is an ordinary shader asset — reference it from a production with shader out.frag.

Channel wiring

For a single-pass file, texture(iChannel0, …) stays a uChannel0 sampler uniform. For multi-pass // pass: files, the engine convention is used:

  • buffer_a → st_buffer_a (folded function); its iChannel0 = external texture (sampler).
  • Subsequent buffers reference the previous one via function call.
  • The image pass sees the last buffer as iChannel0 (folded) and iChannel1 as the live scene (sampler).

Override wiring per-pass with:

// channel: iChannel0 = buffer_a
// channel: iChannel1 = texture:data/textures/noise.png
// channel: iChannel2 = audio
// channel: iChannel3 = keyboard

Standard Shadertoy exports use #iChannelN "spec" lines instead (URLs, file names, or the keywords audio/keyboard/none). Those are parsed per pass, removed from the emitted source, and wired the same way: texture specs become uChannelN samplers listed as bind notes (so the generator can auto-probe local files from data/textures/ or let you load them manually). Multi-channel shaders that sample iChannel0..3 without any channel comment are also handled — every sampled-but-unwired channel is inferred as a bindable texture sampler instead of silently reading black, which is the common case for code pasted from the Shadertoy editor where textures live in the UI.

Previewing in the generator. Converted sampler channels bind through the Texture Channels section of the editor. Each uChannelN the fragment uses gets a Load… button (PNG/JPG/BMP/TGA/GIF, flipped to match Shadertoy’s bottom-left UV origin) and a Clear button. Files named by the source (// channel: iChannelN = texture:…) are auto-probed from data/textures/ on import, and https:// texture URLs are downloaded automatically — the fetch runs on a background thread, the image is cached in data/textures/ (so re-imports bind instantly), and it is bound to the channel the moment the download lands. Shadertoy API asset paths (/media/…, /presets/…) resolve against www.shadertoy.com. While a fetch is in flight the channel shows a live progress bar with the downloaded/expected size (when the server sends Content-Length; otherwise a running byte counter), and a Cancel downloads button stops the whole batch at the next safe point — partial .part files are discarded and every affected channel returns to the unbound default. Transient failures (timeouts, transport errors, HTTP 5xx) are retried automatically with a short backoff before a channel is marked failed; HTTP 4xx responses are treated as permanent and not retried. While a retry is waiting or fetching, the row shows the active attempt (retrying 2/3…), and the attempt count plus base backoff are tunable in Provider settings (Retry attempts, Retry backoff (ms), saved with the rest of the settings file). Only after retries are exhausted does the channel show the error with a Retry button (which re-downloads, discarding any corrupt cached file) and a Load… fallback to pick a local image instead. The same fetch is available headlessly via ns_shader_ai.exe --download-url=URL (it runs the same retry pipeline, with --retry-attempts=N and --retry-backoff-ms=M to tune it). Channel URLs are persisted in the project (.nsshad): reopening a project binds channels from the cached files, and if a cache file was deleted, the texture is re-downloaded from its stored URL automatically. Unbound channels render as tileable neutral noise — the same thing most Shadertoy shaders expect from iChannel0 — instead of the old 2×2 checkerboard placeholder that made every channel-using import preview as a giant checkerboard. Loaded channel images are saved with the project (.nsshad).

Limitations

  • Buffer passes are folded at the image resolution (buffer’s own iResolution is approximated).
  • textureLod and bias arguments are dropped during folding.
  • Audio and keyboard channels are replaced with vec4(0.0).
  • Texture channels cannot be embedded in plain GLSL; the converter lists them as “bind” notes.
  • JSON exports: per-pass inputs are mapped (texture/cube/video → sampler, buffer → folded call, audio/keyboard → stub). outputs are not modelled — a pass that feeds more than one downstream pass is folded once and called by name.

Core workflow

  1. Write or choose a prompt describing the visual, motion, palette, procedural technique and audio response.
  2. Select Fragment Shader, Vertex Shader, or Vertex + Fragment.
  3. Press Generate Shader. The offline built-in provider creates a working starting point immediately.
  4. Watch the real 16:9 OpenGL preview compile. The last valid program remains visible if a later edit fails; use Refresh view or F5 to reset and redraw it immediately.
  5. Adjust metadata parameters, simulated audio, preview speed and resolution, or edit the GLSL source directly. Load a real audio file for FFT reactivity; Play/Pause and Space stop and resume the preview clock together with that audio.
  6. Use Ask AI to Fix after a compile failure, restore a previous generation from history, then save the shader or project.

Generation history stores prior source versions in memory and project files store the prompt, specification, source, preview settings and history. API keys are never written into project files; provider credentials can be saved separately from the Settings panel.

Metadata-driven parameters

Put declarations above the shader code. The workstation parses them and creates live controls in the Parameters panel.

effect.fragglsl
// @param glow float 0.0 8.0 2.0
// @param distortion float 0.0 1.0 0.12
// @param steps int 8 96 48
// @param enabled bool true
// @param color color #00d9ff
// @param direction vec2 1.0 0.0

uniform float glow;
uniform float distortion;

Supported types are float, int, bool, color, vec2, vec3 and vec4. Use Reset parameters to return to metadata defaults.

Audio and performance

Without a track, the simulated audio sliders let you audition bass, mid, treble, kick, snare and overall level. With Load audio..., the existing engine audio analyser drives the same uniform values and displays the loaded track path. Loading audio is isolated from shader document state: the current fragment/vertex source and editor buffers are preserved, and a failed decode keeps the previous source.

The Performance panel reports lightweight source heuristics: approximate ALU size, texture call count, loop count and whether the source looks raymarch-like. Treat this as an early warning, not a benchmark. Ask the AI to optimize for a GTX 1070, then verify the result in the target production.

  • Prefer bounded loops and reuse calculated values.
  • Avoid unnecessary per-pixel texture reads and deeply nested FBM.
  • Keep raymarch iteration counts explicit and moderate.
  • Use the engine's production validation and shader preflight before shipping.

Providers and repair

The default Built-in Demoscene AI is deterministic and offline. It provides prompt-sensitive templates for tunnels, CRT effects, bounded SDF-inspired scenes, glitch effects and plasma, which makes the tool useful without network credentials.

The provider abstraction also supports OpenAI-compatible Chat Completions and Responses endpoints. Configure provider, endpoint, API key, temperature, maximum tokens, and Request timeout (seconds) under View → Settings. The timeout defaults to 600 seconds and can be raised for reasoning models such as gpt-5 or o-series models that may think for several minutes before returning a non-streaming response. Press Refresh available models to query the provider's /models endpoint, then choose the returned model from the selector. Use Save settings to persist the provider configuration; on Windows the API key is protected with the current user's DPAPI credentials and is never written into .nsshad project files. Network generation is opt-in; the application never requires a provider for local generation.

When compilation fails, the previous valid preview is retained. Diagnostics are shown with parsed line/column entries where the driver provides them. Ask AI to Fix sends the current source and diagnostic text to the selected provider and applies the returned source only after the normal compile step.

401 / timeout errors

For 401 errors, paste the complete active project key from the OpenAI dashboard without quotes or a Bearer prefix. The workstation trims surrounding whitespace, quotes and an accidental Bearer prefix before sending the header. For WinHTTP error 12002, the request timed out before the provider responded; raise Request timeout (seconds), especially for reasoning models, then retry. Confirm the endpoint and key belong to the same OpenAI project, then refresh available models again.

Export and integration

  • File → Save Shader As... writes the fragment source and, for pairs, a sibling .vert file.
  • File → Save Project writes a .nsshad companion project with source, prompt, settings and history.
  • File → Copy GLSL copies the current fragment source.
  • File → Copy NSD snippet copies a minimal shader reference for a production script.
