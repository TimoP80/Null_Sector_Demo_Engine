Effect Plugin System

Effects are named, registered content — the engine loop only ever sees names. New content is a class + one registration line; even a shared library can add effects at runtime.

The Effect API

Every effect — built-in or plugin — derives from the base Effect class and implements the lifecycle:

class Effectcpp
class Effect {
public:
    virtual ~Effect() = default;

    virtual void init(EffectContext& ctx) = 0;     // load shaders, build targets
    virtual void render(EffectContext& ctx) = 0;   // draw into the HDR scene
    virtual void resize(EffectContext& ctx) {}     // viewport / target changes

    // helpers the base class provides
    void setTime(float t);          // show clock
    void setAudio(const AudioUniforms& u);  // bass / mid / treble / kick / beat
};
Note

EffectContext carries everything an effect may touch: renderer, camera, shared UBO, assets, the HDR target, and the per-effect uniform map that anim … effect:name.uniform:uX drives. Effects never touch the timeline or scene graph — they are leaf content.

Registration

A process-wide Factory<Effect> is keyed by name. Built-ins register at boot:

src/app/effectreg.cppcpp
void registerBuiltinEffects() {
    registerEffect("intro",  [] { return std::make_unique<IntroFX>(); });
    registerEffect("tunnel", [] { return std::make_unique<TunnelFX>(); });
    registerEffect("cathedral", [] { return std::make_unique<CathedralFX>(); });
    registerEffect("shadertoy", [] { return std::make_unique<ShadertoyFX>(); });
    // … every effect in the content library, by name
}

The demo script addresses effects purely by name — show tunnel { mode 1 }, show shadertoy:plasma.glsl. Adding a new effect to the library means the engine loop changes by zero lines.

Dynamic plugins

Plugins are shared libraries (.dll / .so) dropped into data/plugins/ (or --plugin=DIR). They export a single C entry point that registers into the same factory:

my_effect_plugin.cppcpp
#include "framework/core/factory.hpp"
#include "effects/base_fwd.hpp"

// plugin entry point — loaded via LoadLibrary / dlopen
extern "C" void ns_register_plugins() {
    ns::registerEffect("spiral_stars", [] {
        return std::make_unique<SpiralStarsFX>();
    });
}
  • The engine loads every library in the plugin dir at boot and calls ns_register_plugins().
  • New effect names become available to scripts immediately — same name space as built-ins.
  • Failures are logged, not fatal: a bad plugin never takes the show down.

Built-in content library

The shipped effects are ordinary registered content — the cathedral, neuralnet, infinite machine, voxel city, ghost formation, tunnel, greetings and intro effects, plus the quad generic fullscreen-shader effect and the Shadertoy importer. They're in src/effects/, but nothing about the engine requires them to be.
