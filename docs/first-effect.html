Writing Your First Effect

A full walkthrough: write a fragment shader, wrap it in an effect class, register it, script it into demo.nsd, and animate its uniforms — with the engine's exact APIs, start to finish.

The Effect contract

Every effect — built-in or plugin — derives from Effect and implements a three-method lifecycle. The engine loop never calls anything else; everything it needs arrives through EffectContext.

src/effects/base_fwd.hppcpp
class Effect {
public:
    virtual ~Effect() = default;

    /** build programs + targets once the GL context and assets exist */
    virtual void init(EffectContext& ctx) = 0;
    /** render into ctx->hdr (the target is bound and cleared by the caller) */
    virtual void render(EffectContext& ctx) = 0;
    /** rebuild per-resolution targets after a window resize */
    virtual void resize(EffectContext& ctx) {}
};
FieldWhat it hands you
ctx.rRenderer: fsTriangle (the fullscreen triangle), viewport size (resW/resH).
ctx.assetsFont atlas + metrics (for in-shader glyph drawing).
ctx.timelineBeat/bar/section clock — s.transition, s.beatPulse, section length.
ctx.cameraView/proj, shake and DOF params.
ctx.audioReactive analyser: react.bass, react.kick, react.beat, …
ctx.sharedThe NullBlock UBO (written before render — camera, uBass, uBeat, section state).
ctx.postMusic-driven post params (bloom/glitch/exposure) + prevFrameTex() for handoffs.
ctx.hdrThe current HDR scene target your effect renders into.
ctx.time / ctx.dtShow clock seconds / frame delta.
Shortcut

Most fullscreen effects never need a custom class at all — the built-in SceneFX driver loads any .frag over the fullscreen triangle and handles the shared uniforms, kick flash and music-reactive post params. This tutorial starts with that shortcut, then shows the full class.

Step 1 — the shader

Effects render through the shared fullscreen.vert + your fragment shader. Put the .frag in the shader dir (resolved via NULLSECTOR_SHADER_DIR, default shaders/). Shaders can #include <common> for the shared math + NullBlock UBO, and declare their own uniforms for the animation system to drive.

shaders/mystars.fragglsl
#version 300 es
#include <common>              // shared math + the NullBlock UBO

uniform float uGlow;          // driven by the animation system (anim ... uniform:uGlow)
uniform float uSpin;          // per-scene param set at show time

out vec4 fragColor;           // GL 330 core — never gl_FragColor
in vec2 vUV;                  // 0..1 UV from fullscreen.vert

void main() {
    vec2 uv = vUV * 2.0 - 1.0;
    uv.x *= Null.uRes.x / Null.uRes.y;
    float t = Null.uTime * 0.25 + uSpin;

    // a few rotating star glyphs
    vec3 col = vec3(0.02, 0.03, 0.06);
    for (int i = 0; i < 6; i++) {
        float a = float(i) * 1.047 + t;
        vec2 p = vec2(cos(a), sin(a)) * 0.45;
        float d = length(uv - p);
        col += vec3(1.0, 0.9, 0.7) * uGlow * exp(-d * 18.0);
    }

    // beat pulse + bass hue wobble come from the shared NullBlock UBO
    col *= 1.0 + 0.25 * Null.uPulse;
    col = mix(col, col.gbr, 0.08 * Null.uBass);

    fragColor = vec4(col, 1.0);
}
Note

Effect shaders are written in GLSL ES 3.00 style (#version 300 es, out vec4) — the engine rewrites them to desktop GL 330 core automatically, exactly like cathedral.frag and the other scene shaders. And this is a plain fullscreen shader, not a Shadertoy: if you're porting from Shadertoy, skip this class and use the Shadertoy importer, which handles iTime/iResolution/iChannel* for you.

Step 2 — the class

Two options: the shortcut (SceneFX driver, zero code beyond registration) or a full custom class. The full class gives you per-frame control over uniforms, blending and state.

Option A — the shortcut

Zero code beyond the registration line: the built-in SceneFX driver loads your .frag, applies the shared uniforms, the kick flash, and the extraUniforms map the animation system writes into.

registration only — no class neededcpp
registerEffect("mystars", [](const Value& p) {
    auto e = std::make_unique<SceneFX>("mystars.frag");   // fullscreen driver
    e->mode = p.get("mode").asFloat(0);
    e->renderScale = p.get("renderScale").asFloat(1.0f);
    return e;
});

Option B — a custom class

For per-frame control beyond what the driver offers, subclass SceneFX and override render(). Deriving from SceneFX is what makes anim … effect:NAME.uniform:uX work: the director writes animated values into extraUniforms, and SceneFX::render applies them for you — a bare Effect subclass receives neither uniform writes nor the audio feeds.

src/effects/mystars.hppcpp
#pragma once
#include "effects/scene.hpp"       // SceneFX: fullscreen driver + extraUniforms
#include "framework/core/value.hpp"
#include <memory>

namespace ns {

// Custom effect: extends the driver, adds beat-reactive spin.
class MyStarsFX : public SceneFX {
public:
    explicit MyStarsFX(float spin = 0.0f)
        : SceneFX("mystars.frag"), spin_(spin) {}

    void render(EffectContext& ctx) override {
        // spin accelerates with the beat pulse from the timeline
        const float pulse = ctx.timeline ? ctx.timeline->s.beatPulse : 0.0f;
        extraUniforms["uSpin"] = spin_ * (1.0f + pulse * 0.5f);
        SceneFX::render(ctx);       // applies uFlash/uMode/extraUniforms, draws
    }

private:
    float spin_ = 0.0f;
};

}  // namespace ns
Uniform animation contract

The anim … effect:NAME.uniform:uX command writes into your effect's extraUniforms map — the same contract SceneFX and ShadertoyFX use. As long as your class is a SceneFX (or subclass), the director finds the map and SceneFX::render applies it; override render() only when you need extra per-frame behavior, and call the base at the end.

Step 3 — register it

One line in registerBuiltinEffects() (src/app/effectreg.cpp) makes the name available to scripts — or ship it as a plugin with zero engine changes.

src/app/effectreg.cppcpp
void registerBuiltinEffects() {
    registerEffect("intro",  [] { return std::make_unique<IntroFX>(); });
    registerEffect("tunnel", [] { return std::make_unique<TunnelFX>(); });
    // … existing effects …
    registerEffect("mystars", [](const Value& p) {
        return std::make_unique<MyStarsFX>(p.get("spin").asFloat(0.0f));
    });
}

As a plugin instead, compile the class into a shared library exporting extern "C" void ns_register_plugins() that calls registerEffect("mystars", …), drop it in data/plugins/, and the effect appears without touching the engine at all.

Step 4 — script it

A scene that activates the effect, with construction params and a uniform animation on its uGlow:

data/demo.nsdnsd
scene Stars {
    bars 8   intensity 0.6  chapter 1
    title "My First Effect"
    camera StarCam { rig drift; pos (0,0,2); target (0,0,0); amp 1.2; freq 0.2 }
    show mystars { spin 1.7 }                     // construction params -> factory

    // animate the effect's uGlow uniform across the scene
    at 1 { anim glowPulse effect:mystars.uniform:uGlow smooth {
        0 0.0; 3 2.5; 6 0.8 } }

    at 7 { transition fade 1 }
}

at 60 { show Stars; marker FirstEffect }
Script bitWhat happens
show mystars { spin 1.7 }Instantiates via the registered factory, passing spin into the constructor.
anim glowPulse effect:mystars.uniform:uGlow …Keyframes write into extraUniforms["uGlow"]; your render() applies it every frame.
at 7 { transition fade 1 }Scene exit — the effect keeps rendering until hidden.

Step 5 — iterate live

Edit shaders/mystars.frag and save while the show runs — the shader manager hot-reloads it and the effect picks up the new source next frame. Edit demo.nsd and press F2 to re-parse the whole show. That loop — tweak, save, watch — is the whole point.

Now try

Give it a kick flash: read ctx.audio->react.kick (or the uPulse UBO member) and add it to uGlow. Give it a transition: declare uPrevScene/uTransition and set handoff in the factory. Then export the whole thing as a plugin and your effect is reusable across demos.
