Camera Rigs

The engine provides the camera math — perspective, look-at, handheld shake, depth of field. The rig layer composes that math from data: ten behaviors, each one a camera Name { rig ... } line in the script.

Rig types

RigMotionUsed for
staticFixed pose (pos + target + fov)Poster shots, cards, UI
driftSlow procedural floatThe Awakening intro
flyForward flight through a tubeMachine shafts, the tunnel reprise
naveGliding descent down a naveThe cathedral
orbitOrbit around a target centerSynapse / neuralnet
spiralTighter, faster orbitClimax moments
hoverNear-stationary close-up with tiny driftThe ghost formation
cityHigh flyover above a gridVoxel downtown
descendSlow descending driftDeconstruction
pathCatmull-Rom keyframed splineFull control camera work

Options

Scalar options accept a plain number or a (base, target) ramp driven by the build-up window — so intensity can breathe from amp 1.0 to amp 2.8 across a scene. All options are optional with sane defaults.

OptionRigsMeaning
pos (x,y,z)allCamera position.
target (x,y,z)allLook-at point.
fov N / (base,target)allVertical field of view, degrees.
speed Nfly, city, nave, descendForward speed, world units/s.
radius N · rDrift Norbit, spiralOrbit radius (+ optional drift).
omega Norbit, spiralAngular speed, rad/s.
amp N · freq Ndrift, hoverProcedural sway amplitude / frequency.
sway (x,y,z)fly, orbit, city, …Per-axis sway amplitude.
handheld NallHandheld shake intensity (0 off).
dofFocus N · dofAperture NallDepth-of-field focal distance / aperture.
buildUp (start,end)allRamp window in show seconds for (base,target) options.
descendCap N · descendRate NdescendMax drop / drop per second.
anticipation N · pathDuration NpathPull-back near path end / seconds per spline loop.

In the script

Every scene in the bundled demo opens with a camera rig — this is the entire camera work for the show:

data/demo.nsd — camera rigsnsd
camera IntroCam { rig drift; pos (0,0,2.4); fov (50,58); amp 1.6; freq 0.14; handheld (0.04,0.3) }
camera NaveCam  { rig nave; pos (0,6.5,18); target (0,5.5,0); speed 6.2; fov 58;
                  sway (2.5,1.0,0); freq 0.21; handheld 0.05; dofFocus 12; dofAperture 0.03 }
camera NetCam   { rig orbit; pos (0,1.5,0); target (0,0.8,0); radius 4.5; omega 0.45;
                  fov 64; sway (0,1.8,0); handheld 0.08; dofFocus 5; dofAperture 0.06 }
camera MachineCam { rig fly; pos (0,0,14); speed 6.5; fov 62; sway (1.2,0.9,0);
                    freq 0.33; handheld 0.08; dofFocus 8; dofAperture 0.05 }
camera CityCam  { rig city; pos (0,20,30); target (0,8,0); speed 5; fov 62;
                  sway (6,3,0); freq 0.09; handheld 0.07; dofFocus 14; dofAperture 0.04 }
camera GhostCam { rig hover; pos (0,1.5,3.6); target (0,1.55,0); fov 52;
                  sway (0.5,0.16,0); freq 0.12; handheld 0.03; dofFocus 3.4; dofAperture 0.02 }
camera TubeCam  { rig fly; pos (0,0,14); speed 22; fov 64; sway (0,0,0);
                  freq 0.2; handheld 0.06; dofFocus 9; dofAperture 0.05 }

Path rig

For authored camera moves, rig path drives a Catmull-Rom spline through keyframes (t in 0..1, pathDuration = seconds per loop):

examplensd
camera Crane {
    rig path
    pathDuration 20
    anticipation 3
    path {
        0    pos (0, 2, 10)  target (0, 1, 0)
        0.25 pos (6, 4, 6)   target (0, 1, 0)
        0.5  pos (4, 6, 0)   target (0, 1, 0)
        0.75 pos (-4, 3, -2) target (0, 1, 0)
        1    pos (0, 2, 10)  target (0, 1, 0)
    }
}

Camera nodes in the scene graph can name a rig too (via CamData.rig), so a rig can be reused or driven from scene JSON.
