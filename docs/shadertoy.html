08 Rendering · Shadertoy Import

Shadertoy Importer

Drop a Shadertoy fragment shader into data/shadertoy/, reference it from the script, and it renders fullscreen — mainImage(), the i* uniforms, textures and even multi-pass buffers A–D just work.

Uniform mapping

The importer wraps your code with desktop GLSL 330 and declares the standard Shadertoy uniforms, bound from the engine clock, audio and scene:

Single pass

A file with no pass markers is a single image pass. From the script: load shadertoy plasma.glsl then show shadertoy:plasma.glsl. The effect compiles the shader, creates a fullscreen quad and binds the uniforms each frame.

data/shadertoy/plasma.glsl — exercises every uniformglsl
#define TAU 6.2831853

float hash21(vec2 p) {
    p = fract(p * vec2(123.34, 456.21));
    p += dot(p, p + 45.32);
    return fract(p.x * p.y);
}

void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 uv = (2.0 * fragCoord - iResolution.xy) / iResolution.y;
    float t = iTime * 0.35;
    float q = fbm(uv * 1.6 + vec2(t, -t * 0.7));        // domain-warped plasma
    float d = fbm(uv * 3.2 + q * 1.7 + vec2(t * 0.5, 0.0));

    vec3 col = 0.5 + 0.5 * cos(TAU * (vec3(0.0, 0.33, 0.67) * 2.0 + d * 1.4 + t * 0.12));

    float settle = smoothstep(0.0, 2.0, float(iFrame)); // settle first frames
    col *= 0.35 + 0.65 * settle;

    col = mix(col, col.gbr, 0.02 * sin(iDate.x * 0.0001 + d * 3.0)); // iDate drift

    vec3 ch = texture(iChannel0, fragCoord / iResolution.xy).rgb;    // bound tex or black
    col += ch * 0.18 * (0.5 + 0.5 * sin(iTime * 0.8));

    vec2 q2 = fragCoord / iResolution.xy - 0.5;
    col *= 1.0 - 0.35 * dot(q2, q2);                    // vignette

    fragColor = vec4(col, 1.0);
}

Multi-pass & buffers

Pass markers split the file: // pass: common (shared header code), // pass: buffer_a … // pass: buffer_d, and // pass: image (final composition). Buffers render in order into RGBA16F targets; the image pass composes into the HDR scene.

data/shadertoy/tunnel_warp.glsl (structure)glsl
// pass: common
float tunnel(vec2 uv, float t, vec2 c) { /* ... */ }

// pass: buffer_a
void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    // iChannel0 = external texture or black
}

// pass: image
void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    // iChannel0 = last buffer output
    // iChannel1 = live scene input
}

Note

The show has no cursor, so iMouse stays at zero unless a debug build drives it. iDate comes from the wall clock. Unbound channels sample a 1×1 black texture, so channel code is always safe.

Marker rules (strict)

A pass marker must be the first comment on its own line, with only whitespace before it, and its name is a single token — so prose that merely mentions the marker text never splits the file. These are not markers:

documentation text ≠ pass markersglsl
// Single-pass sample (no `// pass:` markers = image pass).  // prose mention
//   // pass: common   - shared helpers (no program of its own) // nested comment

A trailing comment on a marker line is ignored (// pass: buffer_a - renders into A names the pass buffer_a). The common pass is a header-only pass: its source is prepended to every other pass, so helpers like hash21() or warp() are in scope for buffer and image passes. Content before the first marker is discarded — if you import a Shadertoy export whose shared code sits above the first separator, move it into an explicit // pass: common block. A UTF-8 BOM at the top of the file is tolerated.

Per-file options

A file can carry header directives that change how the importer renders it. Options use the same strict rule as pass markers (first comment on a whitespace-only line, token-exact), so prose can never trigger them.

DirectiveMeaningDefault
// option: renderScale 0.5Render the buffer passes (buffer_a…d) at a fraction of the output resolution — floor(res × scale), clamped to (0, 1]. The image pass and the live-scene snapshot stay full-res. Ideal for heavy multi-pass files whose per-pixel cost is in the buffer passes.1.0 (full res)
data/shadertoy/tunnel_warp.glsl — half-res buffersglsl
// The buffer passes do most of the work (domain-warped fbm), so render them
// at half resolution; the image pass + scene snapshot stay full-res.
// option: renderScale 0.5
Why the buffer passes only

Downsampling buffers cuts the expensive per-pixel cost (fbm, raymarching) by ~4× at 0.5, while the image pass — a cheap texture composite — still runs at full res so the final picture stays sharp. Buffer shaders receive iResolution matching their (scaled) target, so ray/UV math stays consistent.

Measured on the shipped tunnel_warp.glsl at 1600×900 (periodic GPU log line, see below): full-res ≈ 2.25 ms/frame → renderScale 0.5 ≈ 1.10 ms/frame, roughly 2× faster. Not the full 4× of the pixel ratio, because the full-res image pass and the live-scene snapshot are identical at both scales and form the floor.

Verified by the preflight

--check-shadertoy reads each file's declared renderScale, confirms the effect applies it, and verifies the buffer targets are actually sized at floor(res × scale) — a regression (option ignored, wrong size) fails in CI, not mid-scene.

GPU timing

Every shadertoy render is bracketed by GL_TIMESTAMP queries, so the effect knows its own GPU cost. The EMA is logged periodically (~every 2s at 60 fps) so you can see what the renderScale option — or an edit to the shader — is worth live:

stderr, every ~120 frameslog
[INF][SHADERTOY] tunnel_warp.glsl: 1.10 ms/frame GPU (renderScale 0.50, buffers 800x450)
[INF][SHADERTOY] tunnel_warp.glsl: 2.25 ms/frame GPU (renderScale 1.00, buffers 1600x900)

The measured time is only this effect's passes — buffers + scene snapshot + image pass — not the frame. Timestamps (not GL_TIME_ELAPSED) are used because several shadertoy effects can render in one frame and GL allows only one active elapsed-time query per context; a ring of query pairs retries until the GPU finishes, so samples flow whether the loop is vsync'd or running ahead of the GPU.

ToolWhat you see
Live demo[SHADERTOY] <file>: <ms> ms/frame GPU (renderScale <scale>, buffers WxH) — the real per-frame cost at your render resolution.
--check-shadertoy[SHADERTOY-PERF] lines: each file measured offscreen at 1280×720 (median of 40 frames after a 10-frame warmup, so one driver hiccup can't skew it). Scaled files also get the forced-full-res comparison: full-res 0.90 ms -> scale 0.50 0.58 ms (1.55x faster).
Reading the numbers

The check's 1280×720 offscreen times are indicative — absolute ms scale with your resolution, while the ratio transfers reasonably. The authoritative number is the live demo's periodic line at your real resolution. Both are informational: perf is deliberately not a pass/fail criterion (CI boxes differ too much), and a driver without timestamp queries simply prints nothing.

It's a shared timer

This timing is the engine's reusable PerfTimer (src/engine/perftimer.hpp — the GL_TIMESTAMP ring + EMA + profile window). The scene drivers log the same way, so every effect answers "what is this costing?":

[INF][SCENE] cathedral.frag: 2.66 ms/frame GPU
[INF][SCENE] neuralnet.frag: 7.43 ms/frame GPU (renderScale 0.60)
[INF][POST] 0.80 ms/frame GPU (bloom 6 levels)

For scripted A/B comparisons, --perf-json=out.json --perf-seconds=14 runs the show for 14 seconds, then writes one stable sample per effect (median/mean/min/max over the recorded window + frame count) to out.json at exit — run the same script at two renderScale values and diff the medianMs fields.

To see the option's cost over time — e.g. a hot-reloaded renderScale edit, or how the cost sits inside the whole show — use --perf-csv=out.csv --perf-seconds=26 instead: one tab-separated row per second per active effect (t kind name context ms) with its current EMA, plus the post stack:

Live reload

Edit the .glsl source while the demo runs and the importer re-parses and recompiles every pass immediately — the whole multi-pass pipeline rebuilds from disk.
