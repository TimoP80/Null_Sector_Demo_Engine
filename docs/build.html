01 Build & Run

Build & Run

Three CMake targets, one fetch, a handful of flags. The framework core builds without any graphics dependency, so authoring systems can be tested headlessly.

Targets & options

The project requires C++17. GLFW is located via find_package(glfw3); if missing it is fetched from GitHub at configure time. miniaudio and stb are vendored headers in third_party/.

TargetWhat it isGL needed?
ns_frameworkStatic lib: scripting, timeline, animation, scene graph, camera rigs, JSON, assets, file watcher.No
ns_fw_testsUnit tests for the framework core — 253 checks incl. parsing the shipped demo.nsd, a live-reload chain test (watcher → markDirty → reloadDirty), the Log capture sink, and the GL-free Shadertoy pass splitter (plasma → 1 pass, tunnel_warp → common/buffer_a/image).No
ns_demoThe demo app: engine + effects + DemoApp director + GLFW window.Yes
CMake optionDefaultMeaning
NS_BUILD_APPONBuild ns_demo. Set OFF to build only framework + tests with no GLFW.
NS_BUILD_TESTSONBuild ns_fw_tests.
NS_SHADER_DIR / NS_ASSET_DIR / NS_DATA_DIRsource dirsBaked-in base paths for runtime resource resolution.

Runtime directory overrides

At runtime the base directories can be redirected with environment variables (see src/engine/paths.hpp): NULLSECTOR_SHADER_DIR, NULLSECTOR_ASSET_DIR, NULLSECTOR_DATA_DIR. This lets a packaged build point at an external asset set.

Command-line flags

The shell (src/main.cpp) is deliberately thin — every flag exists to select data or to validate, never to encode show logic.

FlagPurpose
--demo=PATHDemo script (default data/demo.nsd).
--track=F1,F2,…Use a specific WAV/MP3 track — a comma-separated list becomes the runtime cycle: the first entry plays at boot and T / Shift+T rotates through the list (whitespace trimmed), instead of the disk scan. Auto-search otherwise.
--no-trackRun with no music file (the show plays silent).
--font=FILETrueType font for text nodes (default assets/fonts/*.ttf).
--plugin=DIREffect plugin directory (default data/plugins).
--windowed / --fullscreenWindow mode. The show defaults to fullscreen.
--window=WxHInitial window size when windowed (default 1600x900).
--check-shadersCompile every engine shader stage plus the app's forward-lit lit program, then exit (CI-friendly).
--check-modelsHeadless-ish 3D pipeline preflight: a generated OBJ cube plus the shipped data/models + data/materials are imported, uploaded and drawn offscreen with a pixel readback. Exits 1 on any failure.
--check-hotreloadLive-reload smoke: boots the app, breaks + fixes a temp shader on disk, and verifies programmatically (manager state + captured log pair) that the broken edit kept the previous program and the fix recompiled it. Exits 0/1 for CI.
--check-shadertoyCompiles and renders every data/shadertoy/*.glsl offscreen with a pixel readback — catches image-pass regressions (frame never reaching the scene target, or a feedback loop collapsing to a solid colour) and verifies per-file // option: renderScale is honored (declared scale == applied scale, buffer targets sized at floor(res × scale)). Also prints [SHADERTOY-PERF] lines — measured GPU ms/frame at 1280×720, plus a forced-full-res comparison for scaled files. Exits 1 on any failure.
--check-production[=PATH]Headless production validator (GL-free): parses the .nsd script, then walks the production checklist — tempo/title/scenes declared, the section schedule is monotonic and fits the duration, every show/effect resolves against the registry, and every referenced file exists (shadertoy, model, material, plugin, post preset, shader, mesh texture, sprite) — printing one ok:/FAIL: line per check and exiting 1 on any failure. The audio-track probe scans the same roots the app auto-searches (data/ + assets/): a missing track is an informational ok: note, not a failure — silent / synth / --no-track shows are valid. Default production: data/demo.nsd. Point it at any script, e.g. --check-production=data/examples/ExampleDemo.nsd.
--smoke-audioHeadless track decode + analyser self-test, then exit.
--perf-json[=PATH]Write one GPU-time sample per effect (shadertoy / scene / particles) plus the post stack to PATH (default perf.json) at exit. Each sample is a stable recorded-window snapshot: medianMs / meanMs / minMs / maxMs / frames, plus effect context (renderScale, buffer size, bloom levels). Scripted A/B of a renderScale option = run twice, diff the medians.
--perf-csv[=PATH]Append one row per second (t kind name context ms, tab-separated) for every active timed effect plus the post stack — the current EMA ms/frame of each, so a renderScale change (or a scene change mid-show) can be plotted over time instead of only dumped at exit. Inactive effects are simply absent from their seconds' rows, which is the plot of what the show cost. Default perf.csv; flushed every row, so it is tail -f friendly. Visualize a capture with python docs/plot_perf.py perf.csv -o perf.png — overlays one line per effect with its final renderScale in the legend (needs pip install matplotlib).
--perf-raw[=PATH]Append one row per collected sample with the unsmoothed ms (t kind name context ms, tab-separated, default perf.raw.csv) — the per-second EMA smooths spikes away, this file keeps them, so stalls and renderScale steps show up as real peaks instead of a gentle slope. One row per new sample (deduped per frame), flushed once a second. Plot with python docs/plot_perf.py --mode=raw -o raw.png.
--perf-seconds=NWith --perf-json, --perf-csv or --perf-raw: auto-exit after N seconds and dump — the show loops forever otherwise, so scripted runs need this.
--editorDockable Demo Editor (Dear ImGui, vendored in third_party/imgui): live preview viewport with the real engine running inside it, scene-graph hierarchy, property inspector (transforms, visibility, per-type payloads — edits go live immediately), timeline lanes with events/markers/sections and click-to-scrub plus a horizontal scrollbar at the bottom (pan the visible window forward through a long show — the handle reflects the zoom share, drag it or click the track to jump, and zooming clamps the window back into range), plus a Fit button (or press F) that snaps the view to the whole show duration and scrolls back to 0 — press again to restore the previous zoom/scroll (any manual zoom or pan leaves fit mode, so the next F re-fits from where you are) — and the whole view window (zoom + scroll + fit state) is remembered per show script in data/editor_state.json (under a timelineViews map keyed by the show's script path, merged on every save so switching shows never loses another show's window): reopening a project — or switching scripts via the browser or a drop — lands exactly on the window you were editing, an audio waveform strip under the lanes (the loaded track's peak envelope in the top half + a live FFT spectrogram heat strip below it - the audio callback captures the mixed output into a rolling spectrum ring and renders it as columns scrolling left from the playhead, real frequency content of the track — flat silence when none is loaded — draggable to scrub) that doubles as a beat-marker editor: amber tick marks show the detected kick transients (windowed-energy peaks over the track's median), and the grid lines can be dragged to re-align the show's BPM grid to the actual track (click a kick tick to snap the grid to it, right-click the strip or use Align beats to kicks in the Audio popup to auto-fit the phase) — the alignment persists per-track in data/editor_state.json — and scrub quantization: press Q to snap the playhead (and the audio) to the nearest aligned grid line instead of free-form, Shift+Q to cycle beat/bar, with a snap beat/bar readout in the toolbar, a captured log console, asset browser, and a profiler with per-effect GPU time. Layouts persist automatically in imgui.ini; View → Reset Layout rebuilds the default docking. Transport: Space play/pause, . step a frame, R restart, F2 reload the script.

Authoring: the Toolbar's + Scene appends a new scene block + activation to demo.nsd (extending the header duration), live-reloads the show and lands the playhead on it; + Asset (also in the Assets panel) opens a dialog that writes Material / Post preset / Scene / Shader / Shadertoy template files into the data/ folders, then applies them to the show (load material, apply preset, or render the shader in the viewport). The TRK button opens the audio source popup — it lives in three always-visible places so it can never be lost (the floating Toolbar can be closed or docked too narrow to show it): right-aligned in the menu bar, in the Timeline header next to Fit (the audio strip is in that panel), and in the Toolbar — plus File → Load Track… and Ctrl+T from anywhere. The popup: pick a .wav/.mp3 from disk (files in cwd, assets/ and data/ are auto-scanned every couple of seconds), type a path, use Browse… — or File → Open Asset — to open a shared asset browser (one popup — deliberately not a modal, so dragging files out onto the scene works — with a category selector: Audio / Texture / Shader / Model / Script; ESC closes it). Each category recursively lists its files under its default folders (assets/, data/, shaders/, the exe dir — or any root you type, with Rescan), and picking one drives a real engine action: Audio loads the track, Texture warms data/textures and assigns it to a selected Sprite node, Shader shows it in the viewport (quad: for .frag, shadertoy: for .glsl; bare .vert files can't run standalone yet and warn), Model warms the OBJ cache under data/models, and Script switches the running demo to the picked .nsd. Double-click or select + the Open button to apply — or drag-and-drop: browser rows are drag sources, so drop a Texture onto a Sprite node in the Scene Hierarchy (the sprite texture switches instantly) or drop any asset (audio, shader, model, script) onto the live viewport to apply it, reusing the exact same pick actions — shaders drop from any folder: a .frag outside shaders/ (e.g. data/shaders) or a .glsl outside data/shadertoy is resolved by its absolute path, so the drop shows the shader instead of failing silently (note: a quad shader shown this way recompiles only on the next show of that shader — scratch Save recompiles via the shader manager, so editing a shader that lives inside shaders/ still hot-reloads live). The viewport also accepts OS-level drops — drag files straight from Windows Explorer or your file manager onto the picture (GLFW drop callback, position-gated to the viewport rect): the extension maps to the same actions as the browser (.wav/.mp3/.ogg/.flac loads the track, .png/.jpg warms the texture cache and assigns it to the selected Sprite, .frag/.glsl shows the shader, .obj warms the model cache, .nsd switches the script). Drops are routed by the panel under the cursor (z-priority, so floating windows win over the viewport) and land on the exact sub-area of split panels: the Timeline takes scripts (.nsd — drop the show's script to switch to it) anywhere, but audio (.wav/.mp3/…) must land on the waveform strip at the bottom (the audio zone — it loads the track asynchronously) while a drop on the lanes above is steered there with a hint toast, and the Console takes shaders on the header/tool row into a shader scratch view — a popup that is now a live source editor: the shader is applied to the viewport and the text is editable in place, with Save (or Ctrl+S, from anywhere in the popup) writing the file back and poking an immediate recompile, so you can tweak a dropped shader and watch hot-reload update the preview — no external editor needed; a * unsaved marker tracks edits, Reload from disk discards them and re-reads the file (e.g. after an external edit), Show in viewport re-applies, and Close/ESC dismisses while a shader dropped on the log list instead filters the console to that shader's lines (compile errors mention the filename — drop-to-debug), the Assets panel opens the browser rooted at the dropped file's own folder, and the Viewport keeps its existing behavior (any asset applies; see above). Dropping a folder on the viewport (or Assets panel) opens the Open Asset popup rooted at that folder with the category inferred from what's inside (a cheap recursive peek — a folder of .wavs opens on Audio, a mixed pack on the dominant type), so you can explore an asset pack straight from Explorer without typing a path; an empty folder just warns. Unrecognized extensions, wrong-type-for-panel drops, or drops not over any panel are ignored with a console warning — and every outcome (apply or ignore) flashes an on-screen toast ring over the viewport (phosphor for applied/loading, amber for ignored, red for a failed load, the last few stacked newest-lowest, each fading out after a few seconds) so the feedback — even from a multi-file drop — is visible without reading the console. Right-click anywhere in the Console (or View → OS Drop History) to open the OS drop history: every drop this session listed with its routed zone (timeline/strip, console/header, viewport, …) and its outcome, newest first, color-coded per row — green for applied/loading, amber for steered/ignored/rejected, red for a failed load — with a hover tooltip showing the full path and the exact drop time. Clicking a record re-runs the action through the same route, and a record that was rejected (wrong zone/panel/type) falls back to the file's canonical action (e.g. audio that was steered off the lanes actually loads the track), with Clear history to reset the list. Each row is also a drag source carrying the same payload as the asset browser: drag a row onto any panel to re-dispatch it elsewhere — the Timeline, Console and Assets panels accept it (with an amber hover border) and route it exactly like an OS drop at the cursor (the waveform strip loads audio, the lanes steer it, the Console header opens the scratch view, the log list filters, Assets browses the file's folder), the viewport applies it through the same judged route as an OS drop (toast + history record included), and Sprite nodes take textures — so a misdropped file can be retried on the right panel, with every re-dispatch itself recorded as a new history entry. A press-drag never accidentally triggers the click-to-re-run. The history is persisted to data/editor_state.json (capped at 200, each entry's timestamp stored as wall-clock epoch seconds) — saved on a 500 ms trailing debounce (a burst of drops — e.g. a multi-file OS drop — writes the JSON once when the window elapses, not once per file, and any save still pending is flushed immediately when the editor exits), so a crash mid-iteration doesn't lose the trail: the next launch restores it and every record stays re-runnable and re-draggable, with Clear history also clearing the persisted copy. When a restored history is non-empty, the editor pushes a blue session-resume marker (14:32:07 session resumed from 2026-08-06) at boot — display-only (no re-run, no drag), so relaunches are visible in the trail. The list auto-refreshes live while the popup is open — files dropped into or removed from the scanned folders appear without pressing Rescan, on a slow cadence scaled to the scan cost so huge roots don't hitch the editor, with an updated flash in the footer confirming the change. Every category remembers its own scan root + last pick (and the last-used category) in data/editor_state.json, so each picker reopens where you were; the panel visibility (Toolbar / Hierarchy / Inspector / Timeline / Console / Assets / Profiler — whatever you hid via the View menu) is persisted too, so a hidden Toolbar stays hidden next launch instead of resurfacing (a state save taken while Fullscreen Preview is hiding the panels persists the pre-preview layout), or stop audio entirely (the popup's No track (silent) button) — the swap happens safely while the audio device is paused and the new track starts at the current show time. Loading a track is asynchronous: the decode runs on a background worker (a decoding … spinner shows in the popup) while the current source keeps playing, and the swap commits with a single device stop/start when ready — large files never block the editor UI. Picking a new track while one is decoding supersedes it cleanly (no spurious failures logged). The chosen track is persisted in data/editor_state.json and restored on the next editor launch (suppressed by --no-track; a missing file warns and keeps the current source). The track browser's scan root + last picked file persist there too (saved whenever the browser closes), so reopening it lands where you were — even in a --no-track session. Scrubbing the timeline (and Restart) re-syncs the music to the show position.

Validation

The repo ships with a battery of offline checks plus headless smokes — run the numbered list below before a release, in order.

terminalbash
# 1. framework unit tests (script parser, timeline, animation, scene graph,
#    JSON round-trips, and validation of every data file in data/)
./build/Release/ns_fw_tests.exe

# 2. compile every engine shader stage + the app's forward-lit program, then exit
./build/Release/ns_demo.exe --check-shaders

# 3. headless-ish 3D pipeline: OBJ import -> lit shader -> draw + pixel readback
./build/Release/ns_demo.exe --check-models

# 4. live-reload smoke: break + fix a temp shader; must keep-previous, then recompile
./build/Release/ns_demo.exe --check-hotreload --no-track

# 5. shadertoy pipeline: render every data/shadertoy/*.glsl offscreen + readback
./build/Release/ns_demo.exe --check-shadertoy

# 6. production checklist: script parses, every referenced asset resolves (GL-free)
./build/Release/ns_demo.exe --check-production

# 7. headless audio decode + analyser self-test
./build/Release/ns_demo.exe --smoke-audio --track=music.mp3

# 8. renderScale A/B: run the same script at two scales, diff the medians
./build/Release/ns_demo.exe --demo=tmp_ab.nsd --perf-json=scale050.json --perf-seconds=14 --no-track --windowed
./build/Release/ns_demo.exe --demo=tmp_ab.nsd --perf-json=scale100.json --perf-seconds=14 --no-track --windowed
#   -> scale050.json vs scale100.json: shadertoy medianMs per effect

# 7. renderScale A/B: run the same script at two scales, diff the medians
./build/Release/ns_demo.exe --demo=tmp_ab.nsd --perf-json=scale050.json --perf-seconds=14 --no-track --windowed
./build/Release/ns_demo.exe --demo=tmp_ab.nsd --perf-json=scale100.json --perf-seconds=14 --no-track --windowed
#   -> scale050.json vs scale100.json: shadertoy medianMs per effect
Tip

Because the demo is data, "the demo" and "the engine" can be validated independently: the tests prove the data files parse, --check-shaders proves the shaders compile, and running the app proves the composition.

The editor's own authoring flows are covered by env-flag headless smokes run under --editor --editor-seconds=10: NS_EDITOR_SCENE_SMOKE=1 (Add Scene appends + reloads + activates), NS_EDITOR_ASSET_SMOKE=1 (New Asset creates a material, post preset and scene, rejects a duplicate name through the dialog's exists gate, and confirms the one-click free-name suggestion is actually free), NS_EDITOR_AUDIO_SMOKE=1 (silence → WAV → silence track swap), and NS_EDITOR_SCRUB_SMOKE=1 (scrubbing re-establishes the scene at the target: a forward scrub into Cathedral activates it, a backward scrub into Intro re-establishes it).
